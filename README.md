# 窗帘对花补裁（Flask + SQLite）

师傅按排法下刀，遇到布疵时改用余布补齐剩下的帘片。本应用根据同花色布料的
**花距、各卷花纹基准、可用区段**和**每对帘片裁长**自动排料，并支持逐片确认已裁。

## 业务规则

- 最多 **3 卷**布、**3 对**帘片；每卷最长 **300 厘米**；位置与长度均为整数厘米。
- 可用区段用半开区间 `[起, 止)` 表示，支持多段，如 `0-120, 150-300`。
- 排料结果按片给出**卷号、起刀位置、止刀位置**，并保证：
  - 每片完整落在所在卷的可用区段内；
  - 同一卷各片互不重叠，且不会占用已裁区段；
  - 对花：同一对两片 `(起刀位置 − 所在卷花纹基准) mod 花距` 余数相同。
- 师傅可按当前排法**逐片确认已裁**，记录写入 SQLite，确认后剩余帘片自动重新排齐。
- **可用区段（或任何参数）一改，旧排法立即失效**，不能再按旧排法确认未裁片，
  需重新生成排法；已裁记录始终保留。
- 排不齐时页面提示“无解”及原因，已裁记录继续保留。
- 已裁记录保护：已有记录时不能减少卷数/对数，也不能改动该卷花纹基准或该对裁长；
  可用区段可以改，但旧排法随参数变更失效。

## 并发与一致性（裁切页 / 参数页同时操作）

师傅在裁切页确认裁片时，另一页可能正在保存参数或重新生成排法。实现约定：

- 所有写请求（保存参数、确认裁片、生成/清除排法、清空记录）都在
  `BEGIN IMMEDIATE` 写事务里完成“读取 → 校验 → 写入”，由 SQLite 串行化，
  不会交叉覆盖。
- **确认裁片先提交**、随后保存参数：保存在事务内看到新已裁记录，若改了该对裁长、
  该卷基准或减少卷/对，整次保存被拒绝并提示原因，数据库保持原样。
- **新参数先提交**、旧排法的确认迟到：确认发现排法指纹与当前参数不符，退回并提示
  “旧排法失效……请重新排料”，不写入任何已裁记录。
- 页面提交的确认表单携带排法指纹与该片坐标；若期间另一页重新排料改动了该片，
  即使参数指纹未变也会退回，要求刷新页面按当前排法确认。
- **手动生成排法不持写锁**：先取参数/已裁记录的版本快照，锁外求解，发布前在同一
  写事务里比对版本。计算期间参数或已裁记录有任何变化，迟到的结果（有解或无解）
  一律作废：有解不发布、不覆盖当前排法，无解也不清除当前排法。
- 求解器本身也会拒绝与当前参数不一致的历史已裁记录（裁长、花纹基准），
  防止旧版本遗留数据被继续错排。

## 升级

`app/db.py` 的建表脚本全部使用 `CREATE TABLE IF NOT EXISTS`，只**新增** `state`
版本表，不重建、不清空既有表。直接对旧库启动新版本即可，SQLite 中的已裁记录、
参数与排法原样保留。

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

SQLite 数据文件位于命名卷 `curtain_data` 的 `/data/curtain.db`，容器重建不丢数据。
Compose 配置了 `/healthz` 健康检查；生产环境请通过环境变量 `SECRET_KEY` 覆盖默认密钥。

## 本地（无 Docker）运行

```bash
pip install -r requirements.txt
DATABASE_PATH=./curtain.db python wsgi.py
# 或开发模式：FLASK_APP=wsgi:application flask --app app run --debug
```

## 求解器说明

未裁帘片建模为约束满足问题，深度优先回溯求解，并采用：

- **容量预检/前向检查**：总长不足或某任务已无可放位置时立即剪枝；
- **MRV（最少可选值优先）**：每次先挑可行分支最少的帘片，显著缩小搜索空间；
- 候选起刀位置按花位余数预计算并按卷号、位置升序枚举，结果**确定可复现**。

问题规模很小（≤3 卷、≤6 片、每卷 ≤300cm），求解在毫秒级完成。
